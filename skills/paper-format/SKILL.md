# paper-format：期刊会议模板、LaTeX 排版与投稿前格式检查

格式即可信度。即便实验扎实，一份用默认工具裸导出的单栏工作稿、公式编号另起一行、表格挤成窄列、页首挂着双语标题和红字占位，也会让审稿人在翻过第一页时就贴上“草稿未完成”的标签。本技能负责将清洁稿件和矢量图准确落入目标期刊或会议的官方模板，在 G6 交付审稿前和 G8 正式投稿前把关所有格式与合规细节。

## 何时使用 / 不适用

适用场景：
- 已选定目标期刊或会议，需要初始化官方 LaTeX 模板并确认页数、摘要、附加组件、匿名与参考文献规则。
- 需要把 Markdown 或草稿正文迁入目标模板，解决公式对齐、伪代码断页、宽表排版、图浮动体位置和编译告警。
- 需要把稿件从一个会议或期刊迁移到另一个目标去向（例如从双栏期刊转为 NeurIPS 或 ACL 模板）。
- 正式投稿、会议答辩、期刊返修或终稿提交前，需要逐项执行匿名脱敏、元数据清理、引用核验、AI 披露检查与视觉逐页排查。

不适用场景：
- 论文结构、科学论证或文字自然度需要大幅重写，这类任务交给 `paper-write`。
- 数据图本身存在统计缺陷、配色混乱或符号错误，这类问题应回 `paper-figure` 在数据源头重绘，切忌只靠 LaTeX 缩放遮掩。
- 需要对学术内容进行模拟审稿打分，交给 `paper-review`。

## 输入

进入本技能前应具备：
1. 作者拍板的单一目标期刊或会议名称，以及当前投稿阶段（初投、会议答辩、期刊返修或终稿 Camera-ready）。
2. 经过 `paper-write` 一致性扫查的章节正文、G4 锁定的 `glossary_and_symbols.md`，以及 `paper-figure` 输出的矢量图文件（PDF/SVG）。
3. 统一的 `.bib` 参考文献库（已做初步文献核实）。

## 流程

按以下六个步骤执行，每一步均有可验证产出。

### 1. 选定单一目标并核查格式档案

先打开 [references/venues.md](references/venues.md)，对照目标期刊或会议当届官方 Author Guidelines 或 Call for Papers 核验模板发布包与版本、栏数、各阶段正文页限（初投、返修/答辩、终稿）、参考文献/附录/Checklist/Impact/Limitations/Ethics 的各自计页规则、摘要字数、必需附带组件与上传位置（如 Elsevier 分刊核验 Highlights 与三项声明、ML 顶会的 Checklist 与模板规定标题的影响声明、ACL ARR 的稿件内 Limitations 与系统问卷）、匿名细则（盲审类型、预印本、匿名链接、补充材料与自引规则）、AI 使用披露要求及参考文献风格。

一份稿件同一阶段只对齐一个投稿目标，严禁混搭不同出版体系的体例（例如把 Elsevier 的 Highlights 和 CRediT 声明塞进会议风格的工作报告里）。所有核验结果必须标注官方指南版本与核对日期，不把往届经验写成绝对硬规则。

产出：项目级格式参数卡（含指南版本与核对日期、`\textwidth`、`\columnwidth`、各阶段页数与计页规则、匿名细则及必需组件适用性与上传位置清单），同步共享给 `paper-figure` 与 `paper-write`。

### 2. 初始化官方 LaTeX 模板（LaTeX 优先）

始终以目标期刊或会议当届官方发布的完整 LaTeX 模板为主工程（如 `elsarticle`、`IEEEtran`、NeurIPS/ICML/ICLR 官方 `.sty`、ACL ARR 官方完整发布包 `acl_latex` 及其中的 `acl.sty`，不要脱离发布包单独拼凑旧样式文件）。按目录隔离正文章节（`sections/`）、矢量图（`figures/`）、表格（`tables/`）与参考文献（`refs.bib`），配置可重复执行的一键编译命令（优先 `latexmk -pdf` 或标准的 `pdflatex -> bibtex -> pdflatex -> pdflatex` 流程）。

Word（`.docx`）只作为中文内部讨论、导师批注或极少数强制仅收 Word 刊物的交付形态。若确需生成内部审阅 Word，严禁使用默认样式裸导出，必须配置定制样式模板并在首页显式标注“内部讨论稿，非投稿版式”。

产出：可零报错编译的官方模板骨架工程。

### 3. 治理公式、算法伪代码与表格排版

把正文填进模板时，参照 `glossary_and_symbols.md` 保持符号统一，并逐类治理高频版面硬伤：
- 数学公式：全部使用 `equation`、`align` 等标准数学环境，遵守目标模板规定的编号位置（右置或左置），确认编号与公式主体无重叠、无越界、无异常掉行，且全部公式交叉引用正常解析；杜绝手工编号；长公式按运算符合理断行并对齐。
- 算法伪代码：使用 `algorithm` 配 `algpseudocode` 或 `algorithm2e`，压缩为可独立阅读的核心步骤，避免跨页把输入输出与主体切开，避免长变量名撑破栏宽强制折行。
- 表格：采用 `booktabs` 三线表（`\toprule`、`\midrule`、`\bottomrule`），移除所有竖线；单元格只放数字与简短标签，长解释移入表注；宽表使用 `table*` 通栏排版或精简列名；跨页长表须遵守编译约束，因 `longtable` 无法直接在双栏输出模式下使用，仅在模板允许单栏模式或单栏附录（如切换 `\onecolumn`）时使用 `longtable` 自动重复表头，双栏模式下则拆分为多张分表并手动重复表头，或按投稿规定移入补充材料；同时确保表题不会孤零零留在页末而数据掉到下一页。

产出：公式、伪代码与表格均编译规范的 `.tex` 源码。

### 4. 统一与核验 BibTeX 参考文献

将所有文献汇总到单一 `refs.bib`，彻底清除任何章节末尾残留的局部引用列表。逐条核查以下四项：
- 完整性：每条文献均补齐作者、题目、年份、正式发表会议或期刊名及页码/卷期，清零“待补”“待核”条目。
- 发表版本升级：将已经被顶会或期刊正式录用的 arXiv 预印本更新为正式发表版本，避免整份文献表清一色都是同年预印本。
- 领域脉络：经典奠基工作与最新进展配比均衡，引用键命名风格全库一致（如 `author2024keyword`），不混用短名键与纯 arXiv 编号。
- 编译清零：排查 `bibtex` 日志中的未定义引用（`?`）、重复键名和缺失必填字段警告。

产出：核验完毕的 `refs.bib` 与零引用告警的编译日志。

### 5. 编译与逐页视觉版面诊断

排版质量绝不能只看 `.tex` 源码判断，必须编译出 PDF 后逐页目视检查：
- 读取编译日志，处理严重的 `Overfull \hbox`（文字或表格冲出页边距）与字体替换告警。
- 逐页浏览 PDF 缩略图与 100% 视图，排查孤立小标题（标题在页末、正文在下一页）、图与首次引用相隔过远、大块异常留白、浮动体堆积到文末、图内文字过小或与正文语言不一致。
- 若发现宽图过扁导致画面拥挤，通知 `paper-figure` 从源头调整画布宽高比重新导出，不要在 `.tex` 里强行拉扯宽高。

产出：逐页视觉排查记录与调优后的定版 PDF。

### 6. 执行投稿前终检清单与分阶段打包

正式投稿或交由 `paper-review` 进入 G7 前，打开 [references/format_checklist.md](references/format_checklist.md) 逐条勾选验证。重点确认匿名脱敏彻底、无任何占位符残留、页数与各附节计页口径达标、目标去向要求的附带文档与问卷（如要求提交时的独立可编辑 Highlights 文件、Paper Checklist、模板规定标题的 Impact Statement、Limitations 专节与系统问卷）全部就位、PDF 字体完整嵌入且文本可正常复制检索。

进入 G8 正式提交时，还须核验目标去向的 AI 使用披露要求，确认已在干净环境复跑核对主表与主图并备妥可匿名的复现说明（环境、版本、复跑命令及受限数据申请方式），同时按初投、会议答辩、期刊返修或终稿阶段输出对应交付包。全部通过后在 `status.md` 记录完成。

产出：已签核的格式终检表与对应阶段的交付包（PDF、按需准备的独立附件、可匿名复现说明及 LaTeX 源码包）。

## 检查清单

- [ ] 稿件严格对齐单一目标期刊或会议的当届官方模板与格式卡核验口径（含指南版本、核对日期、阶段页限与各附节计页规则）。
- [ ] 无 `TODO`、`TBD`、`RED`、`待补`、`待核` 等占位符残留。
- [ ] 已按当届匿名政策彻底剥离作者、单位、致谢、基金号、带身份的代码链接、补充材料隐私及 PDF 元数据。
- [ ] 展示公式遵守模板规定编号位置，无重叠、越界、掉行且引用正常解析；伪代码不从输入输出处硬断页；表格采用 `booktabs` 无竖线、无孤立表题，跨页长表未在双栏模式下误用 `longtable`。
- [ ] 参考文献全部由统一 `refs.bib` 生成，无未定义引用（`?`），无分章残留引用列表，核心预印本已核查正式版。
- [ ] 已逐页目视检查编译后的 PDF，无文字出界、浮动体拥堵、大段异常留白或图片模糊。
- [ ] 目标去向要求的附加部件、系统问卷、AI 使用披露与可匿名复现说明均按适用性、上传位置与当前投稿阶段就位。

## 常见失败

1. 用默认 pandoc 导出 Word 当正式稿件。真实案例（v0.1）用 pandoc 默认样式生成 45 页单栏 Word，导致表格挤成窄列、中英字体混杂、公式编号另起一行落在左侧，审稿人直接判定“不像顶刊稿件”。改法是一律直接使用目标期刊/会议的官方 LaTeX 模板，Word 仅作内部批注稿。
2. 期刊体例混搭且首页残留占位。真实案例中，稿件文首放了超长中文 Highlights、双语标题、作者占位和红字待补，文末又挂着 CRediT 声明与数据地址占位，正文却写得像会议技术报告。改法是先锁死单一目标去向并查清该刊物对各附件的适用性与上传位置，按模板规范保留必需项，其余探索记录移入附录。
3. 表格与伪代码分页断裂，或在双栏中误用 `longtable`。真实案例中，表 2 跨页后续页缺列头且标签频繁折行，表 6 的表题和表头孤零零落在第 30 页末、数据却掉到第 31 页，算法伪代码从输入输出中间跨页切开。改法是通栏宽表控列宽、表题与首行绑定，允许单栏附录时才用 `longtable` 自动重复表头，双栏模式下则拆表并手动重复表头或按规定移入补充材料，并把伪代码压缩到单栏或通栏单页内。
4. 参考文献字段不全且几乎清一色同年预印本。真实案例中，文献表 62 条几乎全是同一年份的 arXiv 预印本，还混用短名键与纯 arXiv 编号，部分条目缺失作者年份，表 1 有 7 行对比方法标着“待核”。改法是统一 BibTeX 核验，补齐领域经典奠基文献并更新已发表版本。
5. 双盲投稿无意泄露身份。常见失误包括把带个人或课题组账号的 GitHub 仓库链接、本地绝对路径、私有源码 commit 编号、带作者名的 PDF Metadata 或致谢基金号留在审稿版里。改法是投稿前专门跑一轮匿名与元数据脱敏检查。

## 与其他技能的衔接

- 上游：接收 `paper-write`（合龙正文）、`paper-story`（`glossary_and_symbols.md`）和 `paper-figure`（矢量图）；在 G5 开始前先向 `paper-figure` 提供目标模板的栏宽和图预算。
- 下游：向 `paper-review` 提供完整编译后的 PDF（G7 审稿必须读排版后的 PDF 与原图，而不是裸 Markdown）；后续按阶段切换回到本技能打包，会议答辩期仅在政策允许时准备修订稿，期刊返修期按编辑信准备干净修订稿并在明确要求时才生成标色对比版（如 `latexdiff`），录用后生成终稿打包。
