# paper-write：逐节起草、翻译润色与全稿一致性

写作的任务是将已经验证的科学论证准确、克制、无摩擦地传达给审稿人。没有论证骨架就开始堆字数，或者把五章同时外包出去各自发挥，最终只会拼出前后打架、数字复读、满篇内部代号的工作报告。本技能负责阶段门 G6 的文本生产与清洗，确保每一句话都有出处，每一处术语与数字全篇统一。

## 何时使用 / 不适用

适用场景：
- 已通过阶段门 G4 与 G5，手头有确认的 `outline.md`、贡献-证据表和定稿图清单，进入阶段门 G6 逐节起草。
- 需要把中文研究草稿翻译为顶刊或顶会标准的英文 LaTeX 文本，或把英文段落直译回中文核对原意。
- 初稿读起来有明显大模型套话、翻译腔、拼装感或篇幅冗长，需要做分层次润色与去 AI 味清洗。
- 全稿初成或返修改完之后，需要做全篇数字、符号、代号、时态和引用的一致性终检。

不适用场景：
- 核心主张尚未确定，或关键实验结果还在变动，应先回到 `paper-evidence` 或 `paper-story`。
- 需要生成或修改目标期刊的 LaTeX 版式、表格跨页、PDF 浮动体布局，这类排版事务交给 `paper-format`。
- 需要对成稿做多模型对抗式打分与可救性评估，应调用 `paper-review`。

## 输入

开始前应备齐以下材料：
1. 作者确认的 `outline.md` 与贡献-证据对照表（来自 `paper-story`）。
2. 定稿 `figure_plan.md` 与图注草稿（来自 `paper-figure`），明确哪些数据由图承载、哪些由表承载。
3. 冻结实验结果表及统计数值（来自 `paper-evidence`），严禁凭记忆写数字。
4. 目标期刊或会议的语言要求、篇幅上限与摘要限制（来自 `paper-format`）。

## 流程

按以下七个步骤单线推进，每一步产出可供下一环节核查的工件。

### 1. 锁定术语表、符号表与内部代号映射表

动笔写正文前，先建立 `glossary_and_symbols.md`（模板见 [references/ai_tells.md](references/ai_tells.md) 末尾）。表内完成三项锁定：
- 内部代号清洗映射：把所有实验周次（如 `W10`、`W11`）、脚本原型名（如 `ours_v2`、`hybrid_audit_v1`、`B_struct_only`）、代码参数（如 `enable_deletes=False`）、临时编号（如 `C2–C4`）、具体报错样本名及哈希盐全部映射为正式学术名称，或明确标为“禁止进入正文”。
- 数学符号唯一化：每个核心概念只对应一个符号（如生命周期先验统一记作 $p_{\text{struct}}$，同步通知图表脚本）。
- 数值精度规范：全篇统一精度标准，例如指标统一保留三位小数，百分比统一保留一位小数，计数大于等于一千统一加千分位逗号。

产出：`glossary_and_symbols.md`。

### 2. 按骨架逐节起草（控制单线连贯）

按“问题形式化与方法 → 实验设置与结果 → 引言 → 讨论与局限 → 相关工作 → 摘要与结论”的顺序逐节写作。即使使用多个 agent 协助，也必须按节串行汇总，由同一主笔先锁死前文符号与口径再写下一节，禁止五章盲目并行直接拼接。

每节严格遵守 `outline.md` 规定的一句话目的与篇幅预算：
- 以科学主张驱动叙事，按“问题 → 机理 → 设计选择 → 消融验证”展开，杜绝按开发时间线讲踩坑流水账。
- 主表与主文只聚焦最终定版方法。已弃用的早期过拟合原型不进主表，只在去偏消融小节作为反面对照简述。
- 尚未补齐的实验或待核文献，集中记录在单独的 `open_items.md` 中，严禁在摘要、正文和表格单元格内散落红字占位。

产出：各章节初稿文件与集中的 `open_items.md`。

### 3. 压缩冗余与厘清章节边界

初稿完成后立即做一次结构瘦身，切除低信息密度段落：
- 核心统计数字只在摘要放 2 至 3 个最关键值，在实验章完整展开，避免同一组数字在摘要、Highlights、引言、相关工作、实验、讨论和结论里换语序重复五到七遍。
- 相关工作保持客观综述视角，不提前塞入本文实验数字，不把源码路径、commit 号和代码行号在相关工作和问题定义里重复抄写两遍（源码细节放附录或脚注）。
- 讨论章负责提炼设计准则、适用边界和失败机理，不重念实验结果表；开销分析换算为每会话平均 token 或延迟，不只贴总账单。

产出：结构压缩后的章节稿，字数回到目标期刊篇幅窗口内。

### 4. 中英学术互译与克制润色

翻译和润色操作采用“角色 / 任务 / 约束 / 自查”四段式规范，把内容修改与语言打磨拆开处理：
- 中译英（LaTeX 目标）：保持公式原样，转义特殊字符（`%`、`\_`、`\&`），不用缩写形式（写 `does not` 而非 `doesn't`），少用方法名所有格（写 `the performance of X` 而非 `X's performance`），同步输出中文直译供作者核对原意是否走样。
- 英译中（逻辑核对）：严格直译保持句式对应，删去 `\cite` 和 `\ref` 等干扰命令，不擅自替原文补全逻辑漏洞，以便暴露英文草稿里的拗口或歧义处。
- 克制润色阈值：先查段落逻辑和主张边界，最后动词句。如果原文已经准确、流畅、符合学术惯例，保留原样并明确标示通过，绝不为了刷存在感强行换近义词，也禁止把平实的中文改成陈旧公文腔（如无故把“旨在”改“拟”、把“是”改“系”）。

产出：目标语言正文与简短修改说明。

### 5. 去 AI 味与自然度清洗

打开 [references/ai_tells.md](references/ai_tells.md)，按清单逐节排查并改写机器味痕迹：
- 替换空洞拔高词与英文高频 AI 词，用具体、平实的动词和量化描述替代情绪渲染。
- 打破机械结构：把正文中过度堆砌的项目符号列表改写为连贯段落；削减滥用的破折号与固定三段排比；检查连续几个小节的结尾，消除同款模具句（如四连“与……不同，本文……”）。
- 清除强贴期刊大帽的话术。如果正文没有建立对应理论模型或引用该领域经典文献，删去硬凑的学科高帽。
- 保持句子长短交错，兼顾信息密度和阅读节奏。

产出：自然度清洗后的终稿文本。

### 6. 全稿单线程一致性扫查

全稿合龙后，必须从头到尾完整通读一次，执行五项硬核对：
1. 数字一致性：正文每处数字与冻结数据、主表和图内标注逐一比对，小数位精度统一。
2. 命名与符号一致性：全文检索是否残留任何旧原型名、周次名、代码字段或符号漂移；检查方法名和变量名与图注、算法伪代码完全吻合。
3. 主张边界一致性：标题、摘要、贡献列表与实验证据逐条对齐，没有把未实现的构想或无实验支撑的修复承诺写进摘要和标题。
4. 时态一致性：英文稿件中，描述本文方法设计、系统结构、图表呈现和普遍结论用一般现在时；描述具体执行过的历史实验步骤或某篇前人工作的特定做法可用一般过去时，全篇保持同一准则。
5. 引用一致性：确认所有引用键均指向统一的参考文献库，删净任何分章末尾残留的“本章引用清单”，核查无未定义引用键或短名与 arXiv 号混用。

产出：全稿一致性扫查记录与修改后的合龙正文。

### 7. 签出 G6 并交接下游

确认正文无散落占位符、无内部代号且已完整通读后，把 `open_items.md` 中仍未闭环的事项如实呈报作者，更新 `status.md` 标记 G6 状态，将清洁文本交由 `paper-format` 编译成目标期刊 PDF。

## 检查清单

- [ ] `glossary_and_symbols.md` 已建立，正文零内部代号、零周次号、零未包装代码字段。
- [ ] 主文和主表全部围绕最终定版方法展开，已弃用原型仅在必要消融中作为反面参照。
- [ ] 未完成项全部集中在 `open_items.md`，摘要、正文和表格中零散落红字占位。
- [ ] 核心数字全篇一致且小数位统一，不存在同一组数据跨章机械背诵五六遍。
- [ ] 相关工作无提前剧透本文结果，讨论章无机械复述实验表。
- [ ] 已对照 `references/ai_tells.md` 清洗空洞词、翻译腔、机械列表与连环模板结尾句。
- [ ] 全稿已单线程通读，符号、时态与图注/表格/引用键全部对齐。

## 常见失败

以下六类问题均直接源自真实初稿（v0.1）被三位审稿人一致指出的“拼装稿”症状：

1. 分章并行生成却无统一合龙接口。案例中，第 1、2、4、6、8 章末尾各自挂着一节“本章引用清单”，第 3、5、7 章却没有；第 4 章引用键带反引号，第 6 章甚至丢了列表符；第 2.1 节与第 3.4 节照着同一份源码笔记，把相同仓库的 commit 号和代码行号原样写了两次。改法是强制合龙通读并统一文末 BibTeX 库。
2. 工程代号与调试细节直接裸露进正文。案例中，正文直接出现 `W11`、`ours_w10_hybrid`、`ours_v2`、哈希切分盐 `sha256("w11-split-v1:" + task_id)`、报错样例名 `shopping_task_002`、未定义的内部编号 `C2–C4` 以及代码字段 `enable_deletes=False`。改法是先建映射表再动笔，合龙时用正则全局扫描下划线标识符和周次号。
3. 按研发编年史写论文，主表仍放已弃用原型。案例中，第 4 章已宣布初版规则 V0 因关键词过拟合而弃用，但第 6 章多数主表和图 6 仍围着旧原型 `ours_v2` 展开，最终方法只占表格角落两行。改法是以最终方法重构整章实验叙事，研发踩坑史只压缩进一段消融。
4. 同一组数字跨章复读五到七遍。案例中，真实系统 `64/80 = 80.0%` 残留率和观测通道使 F1 从 `0.648` 跌至 `0.440` 的数字，从摘要一路背诵到结论六七次，token 账单原样抄三遍却不算单会话开销。改法是规定每组数字的“主落点章节”，其余章节只给高层定性或一句索引。
5. 用满篇红字免责声明掩盖未完成状态。案例中，全稿散布数十处红字占位，连摘要和表 1 都有“待核”，同一句机理待查的免责说明在全文粘贴四五遍。改法是未完成项统一收敛到 `open_items.md`，阻断项未补齐前不假装成稿。
6. 模板化 AI 连接句与强贴期刊帽子。案例中，相关工作四小节结尾清一色使用“与……不同，本文……”；全文频繁喊出“信息融合视角”口号，却没有对应理论建模与奠基文献。改法是按 `references/ai_tells.md` 逐节重塑过渡逻辑，没有理论支撑的学科帽子一律摘掉。

## 与其他技能的衔接

- 上游：`paper-story`（提供 G4 骨架稿与每节一句话目的）、`paper-figure`（提供 G5 图清单与定稿图注）。
- 协同：`paper-crew`（多 agent 写作时的分工约束与交付门把关）。
- 下游：`paper-format`（将清洁正文迁入目标期刊 LaTeX 模板并编译 PDF）和 `paper-review`（G7 对抗审稿；返修阶段再回到本技能按改稿计划精修对应章节）。
