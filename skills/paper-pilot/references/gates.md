# 阶段门详细退出清单（G0–G8）

每一门的所有退出核验项均须满足，才能在 `status.md` 标为“已通过”并进入下一门。若下游审稿或复核暴露上游漏洞，立即按各门底部的回退规则退回。

---

## G0 选题

进入条件：存在初步研究方向。

必交产出：
- 问题陈述（不超过一页，说明研究对象、现实痛点与预期贡献边界）
- 目标期刊或会议清单（主选 1 个，备选 1–2 个）
- 里程碑时间线与阶段验收节点
- 初始化的 `status.md`

退出核验项：
- [ ] 研究问题表述具体，而非宽泛领域口号。
- [ ] 已明确目标去向的篇幅限制、格式要求与大致截稿时间。
- [ ] 研究者本人（及必要时的导师）已确认问题陈述与时间线，并记入 `status.md` 决策记录。

---

## G1 文献

进入条件：G0 已通过。

必交产出：
- 论文矩阵 `paper_matrix.csv`（含年份、来源/录用会议期刊、主题分类、代码情况、阅读状态）
- 精读卡片目录 `cards/`
- 领域空白总结（写清现有工作做到哪里、缺什么、缺口有何证据）

退出核验项：
- [ ] 采用多源检索并补抓近期预印本，已核查本地索引截断时间，无明显漏检。
- [ ] 矩阵覆盖领域经典奠基工作与近期代表工作，无“只收当年预印本”的偏斜。
- [ ] 核心对比论文均已有结构化精读卡（含问题、方法、实验设置、结果、局限）。
- [ ] 能用一段清晰文字概括“现有工作做到哪里、缺什么”，且每句判断有对应卡片支撑。

常见回退触发：进入 G2 或 G3 时发现关键基线未检索到，回退 G1 补录矩阵与卡片。

---

## G2 创新点

进入条件：G1 已通过。

必交产出：
- “瓶颈 × 方法”交叉矩阵与候选创新点池
- 针对每个候选的查新报告（含最近 3 个月预印本）
- 反方质询记录（逐条列出最尖锐的审稿人质疑与最小可证伪实验设计）
- 三选一提案及作者定题记录

退出核验项：
- [ ] 每个进入终选的候选创新点均完成查新，明确与最近 3 个月相近工作的本质区别。
- [ ] 每个候选均经过独立反方质询，写明了失败条件和最小可证伪实验（MVP）。
- [ ] 未出现“仅凭文献排序直接锁定方案”的草率决策。
- [ ] 作者亲自拍板最终方案，并记入 `status.md`。

常见回退触发：G3 原型实验推翻核心假设，或查新撞车，回退 G2 调整方案或切换备选。

---

## G3 证据

进入条件：G2 已通过。

必交产出：
- 实验协议（数据集、切分方式、评价指标、基线清单、计算预算）
- 真实通道复核与诚信检查报告
- 填满的主张-证据对照表（`claim-evidence` 表）

退出核验项：
- [ ] 真实信号核验通过：主实验在真实观测信号下成立，所有由真值派生或加噪的仿真信号均已标记并撤出主结论。
- [ ] 预注册切分与去偏通过：规则、阈值或关键词先验未在看过测试集后手写，开发集与测试集严格隔离。
- [ ] 构造同构检查通过：测试故障或注入样本不是按方法自身检测谓词造出来的，并包含合理反例。
- [ ] 数据完整性核验通过：拉取与统计脚本无默认 `top_k` 或分页截断，样本总数与预期严格一致。
- [ ] 证据链闭环：发现问题的真实数据源与评测方法的数据源已交汇，避免前半篇讲系统 A 现象、方法只评系统 B。
- [ ] 组件独立贡献厘清：在相同候选集与预算下完成消融与统计检验，确认增益来源可解释。
- [ ] `claim-evidence` 表已填满，无证据支撑的主张已删除或明确移入局限清单。

常见回退触发：G7 审稿指出存在构造同构、数据泄漏、消融缺失或方法分量不足，回退 G3 补实验。

---

## G4 故事

进入条件：G3 已通过。

必交产出：
- 一句话核心主张
- 贡献-证据对照表（含研究问题 RQ 与各条贡献的一一映射）
- 8 页以内的骨架稿 `outline.md`（每节一句话目的、段落提纲、待放图表槽位）
- 统一术语与命名表（定义论文用名，列出禁止出现的内部代号）

退出核验项：
- [ ] 题目、摘要要点与贡献列表均严格落在 G3 证据边界内，未做的能力（如修复闭环或未实现分支）不进题目与主贡献。
- [ ] RQ 与贡献条目一一对应，读者能清楚看出哪个实验支撑哪条贡献。
- [ ] 骨架稿篇幅控制在 8 页以内，信息主次清晰，没有跨节重复罗列同一组数字。
- [ ] 论文定位与骨架稿已由作者审阅并签字确认，才能解锁后续画图与分章成稿。

常见回退触发：G6 成稿或 G7 审稿发现叙事失焦、过度声称或定位摇摆，回退 G4 重构骨架。

---

## G5 图

进入条件：G4 已通过。

必交产出：
- 图清单 `figure_plan.md`（每张图先写一句话核心信息）
- 全部正式图表与可复现绘图脚本

退出核验项：
- [ ] 每张图有且仅有一句核心信息，删除信息密度过低的冗余单图或合并为子图。
- [ ] 图 1（teaser）是具体实例（例如一条带时间线的真实样本演变与两路证据对比），不是塞满文字的方框流程图。
- [ ] 方法架构图只画已实现的路径，清晰标出每路输入与交互，未实现的分支不画成并列。
- [ ] 数据图全部反映最终方法结果，不遗留已弃用版本的旧图。
- [ ] 无误导性视觉编码（禁止跨组连线造成配对误读、避免双 y 轴歧义）。
- [ ] 全套图遵守统一字体、字号、留白与色义规范（一种颜色只代表一种含义）。

常见回退触发：G6 或 G7 发现图表数据与最终方法不一致，或图意难以一眼看懂，回退 G5 重制。

---

## G6 成稿

进入条件：G5 已通过。

必交产出：
- 按目标期刊或会议模板编写的完整手稿（LaTeX 优先）
- 更新后的集中待补清单（存于 `status.md` 或独立文件）

退出核验项：
- [ ] 直接基于目标期刊/会议官方模板排版（Word 仅作内部讨论稿，不作准投稿版）。
- [ ] 全文扫描确认无内部代号外露（如实验轮次号、脚本名、旧版本名、哈希盐或本地路径）。
- [ ] 主结果表只加粗最终方法，不加粗已弃用变体；数字不跨章节反复堆砌，摘要仅保留 2 至 3 个最关键数字。
- [ ] 源码路径、commit 号等实现细节移至附录或脚注，不塞入正文形式化定义。
- [ ] 所有未完成项集中列于一处，正文中不散落红字标注。
- [ ] 各章节引用清单与术语命名严格一致。

常见回退触发：成稿时发现某段论证缺实验支撑，停止补编文字，记入待补清单或回退 G3/G4。

---

## G7 审稿

进入条件：G6 已通过。

必交产出：
- 至少 2 家不同模型家族的独立盲审报告 `review_*.md`
- 综合共识与改稿方向的元审稿报告 `meta_review.md`
- 交付门验收记录（见 `paper-crew`）

退出核验项：
- [ ] 主控模型或把关人已完整通读全文，而非仅做数字抽查。
- [ ] 至少 2 家不同厂商模型独立完成审稿，互不抄袭结论，且执行写稿与审稿分离。
- [ ] 审稿意见已区分“表述问题”与“方法缺陷”，并评估每项致命问题的可救性。
- [ ] 三方或两方共识中的致命问题全部清零，或经作者同意正式降格为局限并同步修改题目与摘要。
- [ ] 若元审稿提出路线分叉（如补实验 vs 改定位），已由作者拍板并完成相应回退闭环。

常见回退触发：任一致命问题无法靠文字修改解决，按缺陷类型回退至 G3、G4 或 G5。

---

## G8 投稿/返修

进入条件：G7 已通过。

必交产出：
- 通过编译与格式自查的投稿包
- 参考文献逐条核验记录
- 返修阶段：逐点回复信 `response.md`、修改说明与标红追踪稿

退出核验项：
- [ ] 篇幅、摘要字数、Highlights 长度、图表分辨率与文件命名完全符合目标期刊/会议指南。
- [ ] 参考文献逐条核验作者、年份、标题与出处，已将预印本更新为正式发表版本，并保留关键经典奠基工作。
- [ ] 返修时逐条回应审稿意见，每条回复对应稿件中的确切修改位置，不回避硬伤。
- [ ] 最终提交包经 `paper-crew` 交付门核查并由作者最终确认。
