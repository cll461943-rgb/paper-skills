# 多 Agent 任务单模板（brief_template.md）

每次向外部模型或子 agent 派发工作前，按本模板生成独立任务单。未填清的字段标为待补，禁止口头模糊派活。

---

## 1. 任务元信息

- 任务编号：`T-XXX`
- 所属阶段门：`G1 / G2 / G3 / G4 / G5 / G6 / G7 / G8`
- 任务类型：`code / doc / figure / review / scan`
- 复杂度：`低 / 中 / 高`
- 执行者：`指定模型名称`
- 跨厂商复核者：`必须与执行者不同模型家族`
- 最大返工轮次：`1 轮（未过则升级或由主控模型接管）`

## 2. 目标与上游锚点

- 一句话目标：说明本次只解决什么问题，不顺带做哪些事。
- 必须严格对齐的上游锚点文件：
  - 骨架稿：`outline.md`（若为写稿任务，注明本任务对应哪一节及该节的一句话目的）
  - 主张-证据表：`claim-evidence` 表路径
  - 统一命名表：见第 5 节
- 禁止事项：未经主控模型与作者同意，不得修改论证主线、不得新增表外主张、不得扩写未实现的模块。

## 3. 输入材料清单

逐条列出允许读取的文件路径及用途，不给无关历史草稿，防止模型混用过期数字。

1. `路径 1`：说明其角色（例如主实验汇总表，仅取最终方法列）
2. `路径 2`：说明其角色

## 4. 输出格式与交付路径

- 输出文件路径：`明确相对路径`
- 结构要求：明确章节标题层级、段落顺序、字数或行数范围、JSON/CSV 字段名。
- 写作风格约束：中文/英文目标语言、术语保留规则、缺失数据一律写成“待补”不得编造。

## 5. 统一术语与命名表（写作与绘图任务必填）

| 概念 | 论文正式用名 | 禁止出现的内部代号或旧称 |
|---|---|---|
| 待补 | 待补 | 例如实验轮次号、脚本名、临时版本号 |

## 6. 边界与安全规则

- 不修改允许范围之外的任何文件。
- 不执行未授权的联网、提交或删除操作。
- 不编造任何文献、DOI、实验数值或统计检验结果。
- 遇到输入材料自相矛盾时，暂停臆测，在输出末尾“待确认事项”中列出冲突位置。

## 7. 公开自查标准（执行者提交前逐条自检）

- [ ] 输出路径与格式完全符合第 4 节要求。
- [ ] 每个数字均可追溯到第 3 节提供的输入材料。
- [ ] 全文扫描未出现第 5 节黑名单中的内部代号。
- [ ] 无未完成项散落正文的红字占位，所有待补项集中列在指定位置。

## 8. 主控模型隐藏验收项（不发给执行者，仅主控把关使用）

- 隐藏测试或抽查方案：例如边界输入测试、样本总数无截断核对、与上下游章节的衔接一致性抽查。
- 跨厂商复核重点：提示复核模型重点排查逻辑漏洞、构造同构、过度声称或隐蔽重复。
