# 交付门与验收清单（delivery_gate.md）

交付验收按对象分级启用，不把阶段骨架与完整投稿稿绑在同一套重流程上。缺少对应档位要求的关口，只能以“内部工作草稿”或“预审稿”名义流转，不得声称验收通过。

- **G4 骨架与阶段提案（如 `outline.md`、选题或立项提案）**：启用“G4 阶段验收”，核对证据映射、集中未决项和作者确认，不要求全文通读与跨厂商独立盲审。
- **G7 完整初稿、G8 投稿/终稿包以及重大返修与改稿**：启用“完整五关交付门”，必须走完全文通读与独立审稿流程。

三方职责保持清晰边界：`paper-review` 负责组织审稿并生成、冻结评审记录（`review_*.md` 与 `meta_review.md`）；`paper-crew` 负责核对交付材料与冻结评审指向同一版本并逐项检视本清单；`paper-pilot` 依据核对结果决定是否放行或触发回退，并在 `status.md` 留档。

---

## G4 阶段验收（骨架稿与阶段提案适用）

将骨架稿或阶段提案提交作者拍板前，核对以下四项即可，不必提前消耗全文盲审算力：

- [ ] 证据映射核对：题目、一句话主张、RQ 与贡献条目均能对应到 G3 证据边界，未出现超出实验范围的承诺。
- [ ] 未决项披露：待补数据、风险边界与待决分歧已集中列于清单，没有藏匿在段落中。
- [ ] 术语锚点就位：统一术语与符号表 `glossary_and_symbols.md` 已由 `paper-story` 建立，供 G5 绘图与 G6 写稿共同引用。
- [ ] 作者确认闭环：附上简要交付说明交由作者审阅拍板，确认后由 `paper-pilot` 登记过门并解锁下游。

## 完整五关交付门（G7 完整初稿、G8 投稿/终稿包与重大返修适用）

### 第一关：主控模型通读全文

数字核对脚本不能替代阅读。主控模型必须把交付稿从头到尾连续读完，禁止只抽读前几十行或只搜索关键词。

- [ ] 连续读完摘要、引言、相关工作、方法、实验、讨论、结论及图表说明。
- [ ] 检查跨章节重复：同一组数字或结论是否在多章反复堆砌（摘要只保留 2 至 3 个核心数字）。
- [ ] 检查叙事连贯：问题动机、研究问题（RQ）、贡献条目与实验章节是否一一对应。
- [ ] 检查拼装痕迹：各章人称、时态、术语、符号、引用清单风格是否统一，并与 G4 锁定的 `glossary_and_symbols.md` 一致。
- [ ] 检查内部代号：确认无实验轮次号、脚本名、旧版本名、源码路径或 commit 号混入正文。
- [ ] 检查未完成项：所有待补内容是否集中列在单处清单，正文中没有散落红字标注。

### 第二关：事实、数字、图表与合规底线核对

这一关是底线，不代表质量达标。

- [ ] 正文、表格与图中的每一个数值均能追溯到最终实验产物，三处数值完全一致，统计口径与区间估计对齐 G3 冻结设计。
- [ ] 主表按表注统一标示各列最佳值，正式方法用行标签清晰标识，不混入已弃用变体。
- [ ] 所有数据图均基于最终方法绘制，无旧图残留。
- [ ] 首图按论文类型选定（实例支撑动机时采用具体实例 teaser，发现型论文可用主结果图），且已由未参与绘图者只看图及图注复述比较对象、单位和结论并与 `figure_plan.md` 核对；方法图只画已实现路径；无跨组误导连线或双轴歧义；全套图色义与字号统一。
- [ ] 题目、摘要与贡献条目中没有超出当前实验证据的声称。
- [ ] 若为 G8 外发、投稿或终稿交付：已按目标核查 AI 使用披露，已在干净环境复跑主表与主图并备齐可匿名复现说明，且未越权外发敏感数据、私有代码或审稿意见。

### 第三关：独立盲审、版本冻结与元审稿

交付完整初稿、重大改稿或返修包前，由 `paper-review` 生成并冻结评审，`paper-crew` 核对同版记录：

- [ ] 明确记录独立审稿状态：正式门须满足至少 2 家不同厂商的模型家族分独立会话隔离执行，写稿方不自审，审稿方之间互不透题（禁止把第一家意见喂给第二家）。若外部通道不足、仅能完成单厂商分独立会话隔离审稿，可作为内部预审参考，但必须标明“单厂商隔离预审，正式门待满足”，不得按正式门放行。
- [ ] `paper-review` 已冻结当前交付版本的 `review_*.md` 与 `meta_review.md`，`paper-crew` 已核对审稿输入与待交付稿件为同一版本，无改稿后拿旧评审充数的情况。
- [ ] `meta_review.md` 明确列出多方共识、分歧点以及所有单方提出的致命意见。
- [ ] 每条意见均已区分“表述问题”与“方法缺陷”，并给出“可救性”判断。

### 第四关：逐条复核所有致命意见并清零或降格/回退

对元审稿与各份独立审稿记录中的所有致命意见逐一复核闭环，不仅限于多方共识。只要单方审稿人指出的硬伤经核实成立，同样必须阻断放行，不得带病交付：

- [ ] 可靠改写解决的表述问题：已完成修改并复读确认。
- [ ] 缺乏证据的过度声称：已从题目、摘要和贡献中撤下，降格为局限或未来工作。
- [ ] 涉及真信号失效、构造同构、数据泄漏、数据源错位或方法分量不足的硬伤（无论多方共识还是单方核实发现）：已通知 `paper-pilot` 回退至 G3/G4/G5 补齐，或整理定位选项交作者拍板，未强行交付。

### 第五关：随稿附上诚实的交付说明

每次交付时，必须在回复或文档顶部附上以下交付说明，如实披露验收档位与核查范围，绝不夸大把关程度：

```markdown
### 交付说明
- 交付物、版本与验收档位：`<文件名、版本号；标明 G4 阶段验收 / G7-G8 完整交付门>`
- 评审冻结版本与同版核对：`G7/G8 写明冻结评审对应稿件版本及同版核对结果；G4 填“本阶段不适用”`
- 完整通读范围：`列出主控模型从头到尾完整读过的章节或文件`
- 未读或仅抽查范围：`如实写出；G7/G8 正式交付稿此处应为“无”`
- 独立审稿状态与模型：`正式门已满足（≥2 家跨厂商独立会话：模型 A、模型 B） / 单厂商隔离预审（正式门待满足） / G4 不适用`
- 所有致命意见处置：`列出全部致命意见编号（含单方核实硬伤）及清零、回退或降格状态`
- 合规与复现核对：`G8 写明 AI 披露核查、干净环境复跑与可匿名复现说明状态，以及外发授权情况；非 G8 写“不适用”或已核事项`
- 待作者拍板或集中待补项：`列出需作者决定的方向分叉，及 status.md 中未关闭项编号`
```

## 不予放行红线

出现以下任意一条，立即拦截交付，由 `paper-pilot` 决定退回返工或回退上游阶段门：

1. 属于 G4 阶段验收时，缺少与 G3 的证据映射、隐瞒集中未决项，或未经作者确认签字即试图解锁 G5/G6。
2. 属于 G7/G8 完整交付门时，主控模型未通读全文。
3. 属于 G7/G8 完整交付门时，独立审稿未满足“至少 2 家不同厂商且分独立会话隔离”，或存在“写手自审”，或待交付稿件与 `paper-review` 冻结评审不是同一版本（单厂商隔离仅可标预审，不得按正式门放行）。
4. 仍有未经逐条复核或经核实未处理的致命意见，包括单方审稿人发现且核实成立的硬伤（例如题目承诺的能力完全没有实验支撑）。
5. 正文散落未归口的红字占位或内部工程代号。
6. 属于 G8 外发、投稿或终稿交付时，未按目标核查 AI 使用披露，缺少干净环境主表主图复跑与可匿名复现说明，或存在未授权外发敏感数据、私有代码与审稿意见的情况。
