# paper-evidence：实验协议、诚信复核与证据台账

本技能负责把立项后的设想变成经得起同行推敲的实验证据，对应阶段门 G3（证据）。它贯彻两条铁律：真实信号优先，主张不超过证据。任何实验结果在进入写作前，都必须通过本技能的协议约束与六维诚信审计，并落成完整的主张-证据对照表。

## 何时使用 / 不适用

适用情形如下。

- 已选定研究方案并通过 MVP，准备编写正式实验协议与评测代码。
- 跑出了初步亮眼结果，需要系统排查数据泄漏、仿真信号虚高、规则过拟合、构造同构或接口截断隐患。
- 准备整理最终主表、消融表、统计检验与置信区间，并核验每一条论文主张是否有闭环证据支撑。
- 审稿或自查中发现某条结论站不住，需要重做复核并收窄主张。

不适用情形如下。

- 还在文献调研或海选想法阶段（应先用 `paper-scout` 或 `paper-idea`）。
- 证据已完全锁定，只需规划论文叙述结构和章节写法（应进入 `paper-story`）。
- 只需美化图表配色或重排排版格式（应交由 `paper-figure` 或 `paper-format`）。

## 输入

1. 经作者确认的研究提案、核心主张草稿与 MVP 结论（来自 `paper-idea`）。
2. 待评测的数据集、真实系统或开源基准及其精确版本标识（仓库 commit、数据集版本、模型名称与推理参数）。
3. 现有实验脚本、评测指标定义、脱敏逻辑及结果 JSON 或日志（复核模式必需）。

## 流程

按以下七个步骤推进，设计阶段顺着走，复核阶段逐项过检。

### 步骤 1：编写冻结的实验协议与预注册切分

跑主实验前先写实验协议，明确回答三个问题：测什么指标、独立分析单元 `n` 是什么、要支持哪条统计推断。按固定哈希规则（例如对 `task_id` 哈希）预注册 `dev/test` 切分，所有超参数、阈值与提示词只在 `dev` 上调优，冻结后才在 `test` 上运行一次出结果。若看到测试集失败样本后再改设计，必须显式标为"事后探索"，不得混入预注册结论，正式写进论文前需在独立切分或新样本上重跑验证。

可检查产出：`experiment_protocol.md`（含精确版本、独立单元定义、切分哈希规则与基线清单）。

### 步骤 2：排查观测通道与信息泄漏（真实信号优先）

逐一审计实验里用到的所有观测信号、特征与输入字段。凡是由真值标签加噪声生成的仿真观测通道，必须标红并执行"真实通道复核"（改用真实系统回执、真实验证器或真实日志对比结果）。同时检查脱敏后的数据是否残留隐式泄漏字段（例如默认保留的 `trust_score`、带标签的 ID 前缀，或在重放提示词中意外暴露给 LLM 的辅助分值）。

可检查产出：观测通道清单（注明是否触碰真值）与脱敏字段审计记录。

### 步骤 3：执行先验去偏检查

审查方法里所有的启发式规则、先验权重、正则模式与关键词表。只要某条规则是在看过评测数据后针对性写出来的，就必须做三档消融：原规则、纯领域无关结构信号（不读特定文本词表）、通用数值或格式检查。若去掉基准专属词表后泛化性能持平甚至更高，立刻冻结去偏后的版本作为正式方法，禁止把测试集过拟合增益写进论文。

可检查产出：先验去偏消融表与冻结方法规范声明。

### 步骤 4：执行构造同构检查（防同义反复）

检查测试样本或注入故障的生成逻辑是否与方法的检测谓词同构。如果测试集是照着方法的检测规则造出来的，高分只说明程序正确识别了自己写的规则。整改要求包括：尽量采用独立轨迹或真实系统自然产生的样本，测试构造与人工标注过程屏蔽方法内部逻辑与审计输出，并主动混入合法恢复、时态并存等易诱发误报的反例。

可检查产出：样本生成独立性审查记录与反例覆盖清单。

### 步骤 5：执行数据完整性与组件归因检查

核验数据读取链路的每一个边界：检查 API 或数据库接口是否存在默认截断（如默认 `top_k`、分页遗漏或静默丢弃），核对实际入模样本数与基准宣称总数是否一致，验证基线是否在相同候选池与同等调用预算下公平运行。对多组件方法必须做拆解消融（例如同一候选预算下比较单组件、简单并集、共现过滤、边置换与完整机制），说清每个核心组件的独立贡献，不留黑箱增益。

可检查产出：样本计数核对表与组件归因消融结果。

### 步骤 6：执行统计检验与规范报告

明确区分独立实验单元 `n` 与技术重复或映射扰动。同一组固定 LLM 缓存信号只改匿名 ID 跑多种子时，标准差趋近于 0，必须如实说明这不代表模型本身的调用方差。主比较优先报告差值估计与 95% 配对 bootstrap 置信区间，给出样本量、效应量与精确检验定义，不用单薄的显著性星号替代区间估计，也不把统计相关升格为因果机理。缺失信息一律写 `待补`，不编造统计量。

可检查产出：带配对 bootstrap 区间与单元说明的统计结果汇总表。

### 步骤 7：填写主张-证据表并出具复核报告

将所有通过核查的实验结论填入 [references/claim_evidence.md](references/claim_evidence.md) 形成主张-证据对照表，再按 [references/audit_report.md](references/audit_report.md) 出具完整的实验复核报告。凡是无法通过上述审查的主张，立刻标记为"需收窄"或"已推翻"，严禁带病流入 `paper-story`。

可检查产出：`claim_evidence.md` 与 `audit_report.md`。

## 检查清单

- [ ] 主实验结论在完全不触碰真值的真实观测通道下成立，仿真通道仅作可控对照或已剔除。
- [ ] `dev/test` 切分在调参前预注册固定，所有事后探索均已单列且未冒充正式结论。
- [ ] 已做先验去偏检查，正式方法不含看过测试集后手写的关键词名单或硬编码实体正则。
- [ ] 已做构造同构检查，测试样本独立于方法谓词，并包含合法恢复等反例。
- [ ] 已核验接口分页、默认 `top_k` 截断与脱敏字段，样本总数与原始基准逐条对齐。
- [ ] 多组件方法已在同候选、同预算下完成消融，各组件独立作用清楚。
- [ ] 统计报告写清独立单元 `n`、差值与 95% 配对 bootstrap 区间，未将映射种子方差误报为模型随机性。
- [ ] 主张-证据表每条主张均有明确数据指向，无证据支撑的条目已删除或降格。

## 常见失败

1. 仿真观测通道与推理模型同构，造成指标严重虚高。在 LLM agent 记忆审计项目中，早期实验用真值故障集加固定噪声（η=0.10）生成回合与探针信号，生成过程和推理模型共享 Noisy-OR 结构，LME 子集定位 F1 虚高至 0.648。换成真实 LLM 验证器通道后，实际噪声远高于假设且漏报远多于误报，定位 F1 跌至 0.440，低于简单的逐条核查基线（0.675），原主张直接被推翻。规避办法是强制执行真实通道复核，永远不把真值派生信号当成真实评测。
2. 看过测试集后手写规则先验，导致隐蔽过拟合。同一项目中，初版规则先验塞进了看过全部测试数据后整理的关键词名单、硬编码短语与实体前缀正则。做先验去偏后，只保留不读文本的生命周期信号，在官方测试集上与原规则持平，在新样本上 LocF1 反而高出 +0.050（95% 配对 bootstrap 区间 [+0.020, +0.081]）。规避办法是冻结规则前必做领域无关去偏消融。
3. 测试样本按方法检测模式构造，陷入同义反复。新注入的过期记忆样本直接按方法的生命周期检测谓词构造，导致新样本得分极高却被三方审稿人质疑增益来自构造同构。规避办法是由独立轨迹或真实系统自然生成测试例，屏蔽审计代码，并补足合法反例。
4. 存储接口默认截断引发统计失真。实验脚本调用 `get_all` 时忽略了默认 `top_k=20` 上限，导致 16 个会话的数据未取全，关键比例事后从 76.8% 修正为 80.0%。另有脱敏流程意外保留了带区分度的 `trust_score` 字段。规避办法是把接口上限、样本总数与字段白名单纳入必检的数据完整性清单。
5. 未做预注册切分导致阈值方向冲突。默认阈值 0.55 在一个子集上偏低、在另一个子集上偏高，暴露出阈值并非来自独立开发集。规避办法是先哈希切分 `dev/test`，再在 `dev` 上定型所有超参。

## 与其他技能的衔接

- 上游来源：接收 `paper-idea` 经作者确认的提案与 MVP 结论。
- 异常回退：若真实通道复核或构造同构检查推翻了核心主张，立即记录回退原因并返回 `paper-idea` 重定方案或切换论文定位。
- 下游去向：通过 G3 门控的 `claim_evidence.md` 与 `audit_report.md` 直接移交 `paper-story`，作为编写一句话主张、贡献表和骨架稿的唯一事实依据；统计规范与区间数字同时流向 `paper-figure` 与 `paper-write`。
