# paper-evidence：实验协议、诚信复核与证据台账

本技能负责把立项后的设想变成经得起同行推敲的实验证据，对应阶段门 G3（证据），并在阶段门 G2 探路执行时提供无泄漏规范。它贯彻两条铁律：真实信号优先，主张不超过证据。任何实验结果在进入写作前，都必须通过本技能的协议约束、合规核查与六维诚信审计，并落成完整的主张-证据对照表。

## 何时使用 / 不适用

适用情形如下。

- 处于 G2 探路执行阶段，需要为 MVP 试跑提供无泄漏与真实通道约束。
- 作者已选定试跑方案并通过 G2 探路执行（或带预算待验证标记进入 G3），准备编写正式实验协议与评测代码。
- 跑出了初步亮眼结果，需要系统排查数据泄漏、仿真信号虚高、规则过拟合、构造同构、接口截断或授权合规隐患。
- 准备冻结统计口径、整理最终主表与消融表，并核验每一条论文主张是否有闭环证据支撑。
- 审稿或自查中发现某条结论站不住，需要重做复核并收窄主张。

不适用情形如下。

- 还在文献调研或海选想法阶段（应先用 `paper-scout` 或 `paper-idea`）。
- 证据已完全锁定，只需规划论文叙述结构和章节写法（应进入 `paper-story`）。
- 只需美化图表配色或重排排版格式（应交由 `paper-figure` 或 `paper-format`）。

## 输入

1. 经作者选定的研究提案、核心主张草稿，以及 G2 探路执行的 MVP 记录（含实际试跑结果、代码与数据版本、通过线与放行或止损决定；若预算不足标为待验证，须写明进入 G3 后优先补测的范围），来自 `paper-idea` 与 G2 探路阶段。
2. 待评测的数据集、真实系统或开源基准及其精确版本标识（仓库 commit、数据集版本、模型名称与推理参数）。
3. 现有实验脚本、评测指标定义、脱敏逻辑及结果 JSON 或日志（复核模式必需）。
4. 合规与外发授权材料（按需）：涉及人类参与者或敏感数据时，采集前登记的伦理审批或豁免记录、知情同意范围与数据许可；涉及外部模型调用或材料外发时，授权共享的材料清单、接收方与服务数据留存设置。

## 流程

按以下七个步骤推进，设计阶段顺着走，复核阶段逐项过检。

### 步骤 1：编写预先冻结的实验协议、授权登记与组级切分

跑主实验前先编写带日期与版本号的实验协议，由本技能统一冻结后续全流程共用的实验与统计口径，明确回答五类问题：
- 统计设计：冻结指标定义、统计目标量、独立分析单元 `n`、配对或聚类结构、分母口径、失败/超时/缺失样本处理规则、预先指定的主比较，以及与数据结构匹配的区间估计方法（供 `paper-figure` 与 `paper-story` 直接引用）。
- 共享来源分组与切分：冻结 `dev/test` 切分前，先识别数据的共享来源，按用户、会话、原始轨迹或近重复簇分组，再对组执行切分，并显式检查 `dev` 与 `test` 在各共享来源上的交集为零；保存完整的切分清单文件与冻结版本号，不得仅按单条样本 ID 简单哈希切分。所有超参数、阈值与提示词只在 `dev` 上调优，冻结后才在 `test` 上运行一次出结果。
- 术语界定：仓库内带日期与版本号的实验协议称为“预先冻结”；只有具备外部可核验登记记录（如公开时间戳登记号或第三方平台存档）时，对外才称“预注册”并附该登记记录。
- 合规与外发授权：涉及人类参与者或敏感数据时，在采集前登记伦理审批或豁免、知情同意范围与数据许可；向外部模型接口或合作方派单前，记录授权共享的材料范围、接收方及服务数据留存设置，审稿意见、私有代码与原始数据严格按授权范围共享。
- 复现基线：预先记录运行环境、依赖版本、复跑命令及受限数据的合规申请方式，确保 G8 阶段可在干净环境复跑主表与主图并整理可匿名的复现说明。

若看到测试集失败样本后再改设计，必须显式标为“事后探索”，不得混入预先冻结结论；任何据此调整的版本须在独立的新留出集上完成复验后才能正式写入主线。

可检查产出：`experiment_protocol.md`（含冻结日期与版本、统计设计冻结项、共享来源分组与组级切分清单、交集为零检查记录、授权与伦理登记、基线清单及复现入口；若对外称预注册则附可核验登记记录）。

### 步骤 2：排查观测通道、信息泄漏与外发边界（真实信号优先）

逐一审计实验里用到的所有观测信号、特征与输入字段。凡是由真值标签加噪声生成的仿真观测通道，必须标红并执行“真实通道复核”（改用真实系统回执、真实验证器或真实日志对比结果）。同时检查脱敏后的数据是否残留隐式泄漏字段（例如默认保留的 `trust_score`、带标签的 ID 前缀，或在重放提示词中意外暴露给 LLM 的辅助分值），并核查送往外部模型或外发脚本的字段严格限定在已登记的授权范围内，不夹带未授权原始隐私数据或私有源码。

可检查产出：观测通道清单（注明是否触碰真值）、脱敏字段审计记录与外发材料边界核查记录。

### 步骤 3：执行先验去偏检查

审查方法里所有的启发式规则、先验权重、正则模式与关键词表。只要某条规则是在看过测试集或评测数据后衍生出来的，该规则及其对照消融（例如对比原规则、纯领域无关结构信号与通用数值或格式检查）一律标作“探索性分析”，不能直接把原测试集上的消融结果充当正式验证结论。若去偏后的通用版本在探索中表现持平或更稳健，须先将其提交到独立的新留出集完成复验，复验通过后再冻结为正式方法，禁止把测试集过拟合增益写进论文主结论。

可检查产出：探索性先验去偏消融表、新留出集复验结果与冻结方法规范声明。

### 步骤 4：执行构造同构检查（防同义反复）

检查测试样本或注入故障的生成逻辑是否与方法的检测谓词同构。如果测试集是照着方法的检测规则造出来的，高分只说明程序正确识别了自己写的规则。整改要求包括：尽量采用独立轨迹或真实系统自然产生的样本，测试构造与人工标注过程屏蔽方法内部逻辑与审计输出，并主动混入合法恢复、时态并存等易诱发误报的反例。

可检查产出：样本生成独立性审查记录与反例覆盖清单。

### 步骤 5：执行数据完整性与组件归因检查

核验数据读取链路的每一个边界：检查 API 或数据库接口是否存在默认截断（如默认 `top_k`、分页遗漏或静默丢弃），核对实际入模样本数与基准宣称总数是否一致，验证基线是否在相同候选池与同等调用预算下公平运行。对多组件方法必须做拆解消融（例如同一候选预算下比较单组件、简单并集、共现过滤、边置换与完整机制），说清每个核心组件的独立贡献，不留黑箱增益。

可检查产出：样本计数核对表与组件归因消融结果。

### 步骤 6：执行统计推断与规范报告

严格按照步骤 1 冻结的统计设计执行计算与报告，确保方法选择由数据结构决定，而非套用单一固定公式：
- 明确区分独立实验单元 `n`、聚类层级与技术重复或映射扰动。同一组固定 LLM 缓存信号只改匿名 ID 跑多种子时，标准差趋近于 0，必须如实说明这不代表模型本身的调用方差。
- 区间估计按数据结构匹配：独立配对比较时，同步重采样两种方法对应的独立单元，并在每次重采样后整体重算聚合指标（例如重算整体 F1 差值）；会话内多轮或存在嵌套相关性的数据，按会话或更高独立层级进行聚类抽样；仅对独立二项比例，才可直接采用 Wilson 置信区间。
- 写清每一项指标的分母、失败/超时/缺失样本的处理方式以及预先指定的主比较。
- 将区间估计与假设检验分开单列：若在区间估计之外另做假设检验，须记录具体检验方法、单双侧口径与多重比较校正处理；不用单薄的显著性星号替代区间估计，也不把统计相关升格为因果机理。缺失信息一律写 `待补`，不编造统计量。

可检查产出：按冻结统计口径生成的区间估计表、单列的假设检验与多重比较记录，以及单元与缺失处理说明。

### 步骤 7：填写主张-证据表并出具复核报告

将所有通过核查的实验结论填入 [references/claim_evidence.md](references/claim_evidence.md) 形成主张-证据对照表，再按 [references/audit_report.md](references/audit_report.md) 出具完整的实验复核报告。凡是无法通过上述审查的主张，立刻标记为“需收窄”或“已推翻”，严禁带病流入 `paper-story`。

可检查产出：`claim_evidence.md` 与 `audit_report.md`。

## 检查清单

- [ ] 主实验结论在完全不触碰真值的真实观测通道下成立，仿真通道仅作可控对照或已剔除。
- [ ] `dev/test` 切分前已识别用户、会话、原始轨迹或近重复簇并按组切分、检查交集为零，已保存切分清单与冻结版本；仅在具备可核验外部登记记录时对外称“预注册”，事后探索均已单列。
- [ ] 已做先验去偏检查；测试集衍生规则及其消融均已标作探索，据此选定的版本已在新留出集上完成独立复验。
- [ ] 已做构造同构检查，测试样本独立于方法谓词，并包含合法恢复等反例。
- [ ] 已核验接口分页、默认 `top_k` 截断与脱敏字段，样本总数与原始基准逐条对齐。
- [ ] 多组件方法已在同候选、同预算下完成消融，各组件独立作用清楚。
- [ ] 已在协议中冻结指标、目标量、独立单元或聚类层级、配对结构、分母与失败/缺失处理、预先指定的主比较及匹配的区间方法（独立配对同步重采样重算整体指标，多轮按会话或更高独立层级抽样，仅独立二项比例用 Wilson），另做假设检验时已单列并记录多重比较处理，未将映射种子方差误报为模型随机性。
- [ ] 涉及人类参与者、敏感数据或外部模型调用时，已登记采集前审批/豁免、同意范围、数据许可、授权材料、接收方与服务留存设置；已备齐干净环境复跑主表主图所需的环境、版本、命令及受限数据申请说明。
- [ ] 主张-证据表每条主张均有明确数据指向，无证据支撑的条目已删除或降格。

## 常见失败

1. 仿真观测通道与推理模型同构，造成指标严重虚高。在 LLM agent 记忆审计项目中，早期实验用真值故障集加固定噪声（η=0.10）生成回合与探针信号，生成过程和推理模型共享 Noisy-OR 结构，LME 子集定位 F1 虚高至 0.648。换成真实 LLM 验证器通道后，实际噪声远高于假设且漏报远多于误报，定位 F1 跌至 0.440，低于简单的逐条核查基线（0.675），原主张直接被推翻。规避办法是强制执行真实通道复核，永远不把真值派生信号当成真实评测。
2. 看过测试集后手写规则先验，导致隐蔽过拟合。同一项目中，初版规则先验塞进了看过全部测试数据后整理的关键词名单、硬编码短语与实体前缀正则。做先验去偏后，只保留不读文本的生命周期信号，在原测试集探索对照中与原规则持平，在独立新样本上 LocF1 反而高出 +0.050（95% 配对 bootstrap 区间 [+0.020, +0.081]）。规避办法是把测试集衍生规则及其消融标作探索，选定的去偏版本须在新留出集复验通过后再冻结。
3. 测试样本按方法检测模式构造，陷入同义反复。新注入的过期记忆样本直接按方法的生命周期检测谓词构造，导致新样本得分极高却被三方审稿人质疑增益来自构造同构。规避办法是由独立轨迹或真实系统自然生成测试例，屏蔽审计代码，并补足合法反例。
4. 存储接口默认截断引发统计失真。实验脚本调用 `get_all` 时忽略了默认 `top_k=20` 上限，导致 16 个会话的数据未取全，关键比例事后从 76.8% 修正为 80.0%。另有脱敏流程意外保留了带区分度的 `trust_score` 字段。规避办法是把接口上限、样本总数与字段白名单纳入必检的数据完整性清单。
5. 未先做共享来源分组并预先冻结切分导致阈值方向冲突。默认阈值 0.55 在一个子集上偏低、在另一个子集上偏高，暴露出阈值并非来自独立开发集。规避办法是先按用户、会话、原始轨迹或近重复簇分组再切分 `dev/test`、核验交集为零并保存冻结切分清单，在 `dev` 上定型所有超参。

## 与其他技能的衔接

- 上游来源：在 G2 探路执行阶段为 MVP 试跑提供无泄漏规范；作者选定试跑方案并通过 G2 后，接收 `paper-idea` 的提案与 MVP 执行记录（实际结果、版本、通过线与放行决定）进入 G3 正式实验；若 G2 未通过则退回候选池，预算不足标记待验证的条目须在 G3 优先补测。
- 异常回退：若真实通道复核或构造同构检查推翻了核心主张，立即记录回退原因并返回 `paper-idea` 重定方案或切换论文定位。
- 下游去向：通过 G3 门控的 `claim_evidence.md` 与 `audit_report.md` 直接移交 `paper-story`，作为编写一句话主张、贡献表和骨架稿的唯一事实依据；冻结的指标、目标量、分析单元、区间方法、区间数字及复现入口同步流向 `paper-figure`、`paper-write` 与 G8 复现核查。
