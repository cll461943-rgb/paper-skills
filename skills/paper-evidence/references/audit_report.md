# 实验诚信复核报告模板

使用说明：在宣告 G3（证据）通过前，由独立复核者（或换用不同模型/独立会话）对照代码、数据与输出日志逐项填完本报告。存在未解决的致命项时，禁止放行进入写作阶段。

---

## 1. 复核对象与范围

- 复核日期: `YYYY-MM-DD`
- 复核范围: 写明完整检查了哪些脚本、缓存 JSON、日志与统计表，哪些部分未检查
- 代码与数据版本: 仓库 commit / 数据集版本 / 环境依赖说明
- 逐位复现核对: 重跑核心统计脚本是否与汇报 JSON 一致（通过 / 差异说明）

## 2. 六维诚信核查明细

| 核查维度 | 核查方法与查看的具体文件 | 发现与证据 | 判定 |
|---|---|---|---|
| 1. 真实观测通道 | 检查信号生成逻辑是否读取真值或共享推理模型结构 | 待补 | 通过 / 致命 / 需整改 |
| 2. 数据与字段泄漏 | 检查脱敏白名单、提示词拼接字段与隐藏评分列 | 待补 | 通过 / 致命 / 需整改 |
| 3. 预注册切分 | 核查超参/阈值选取是否严格限于 `dev`，事后探索是否隔离 | 待补 | 通过 / 致命 / 需整改 |
| 4. 先验与规则去偏 | 检查是否存在测试集派生词表、硬编码实体正则并查去偏消融 | 待补 | 通过 / 致命 / 需整改 |
| 5. 构造同构检查 | 比对测试样本构造脚本与方法检测谓词，检查反例是否充分 | 待补 | 通过 / 致命 / 需整改 |
| 6. 数据完整性与统计规范 | 检查分页/`top_k` 截断、样本总数、独立单元 `n`、方差含义与配对 CI | 待补 | 通过 / 致命 / 需整改 |

## 3. 基线公平性与组件归因检查

- 所有基线是否使用相同的候选集、模型与调用预算: 是 / 否（说明差异）
- 核心机制是否通过单组件、并集与置换消融，排除"纯拼接"质疑: 是 / 否（说明）
- 问题数据源与主方法评测数据源是否构成同一闭环: 是 / 否（说明）

## 4. 问题清单与整改追踪

按严重度分级记录。`P0 致命` 必须清零或据此收窄主张；`P1 重要` 需在进入 G6 成稿前修复；`P2 提示` 可在方法或附录中说明。

- `[P0]` 问题描述: 待补
  - 代码或数据证据: 待补
  - 对论文主张的影响: 待补
  - 整改方案与复验结果: 待补
- `[P1]` 问题描述: 待补
  - 证据与整改要求: 待补

## 5. 复核结论与门控决定

- 门控结论: 放行进入 G4（故事） / 整改后复核 / 回退至 G2（重定创新点或论文类型）
- 允许进入论文主线的主张编号: `C1, C2...`
- 明确禁止写入题目与摘要的内容: 待补
